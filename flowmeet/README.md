# FlowMeet

Макеты устройства, не сервер.

- `flowmeet-mobile/index.html` — телефон
- `flowmeet-desktop/index.html` — рабочий стол
- `flowmeet-shared/data.js` — общие данные для обоих

Живой установщик 0.2.0 сюда не кладём.

## Экран и API

Цели и сценарии — файлы в `Требования/` (Ц-1…Ц-5). Правила живого экрана — `.cursor/rules/`. Это оригиналы этой рабочей среды. Если их нет в другом клоне — копировать отсюда, не писать заново. Вкладка «Постановка» частично повторяет состав и **не** заменяет эти файлы.

Контракт устройства и приёма звука — существующий `http-call-recorder` (`enroll` / `stream` / `audio`): ключ, пропуск, файл, источник. Второй стек не выдумывать.

Перед правкой интерфейса сверяться с этим API, не со снимком чужого изделия.

1. **На экране только то, что API отдаёт или принимает.** Нет поля в контракте — нет живой цифры и кнопки. Пример: заряд и «свободно ГБ» на карточке диктофона в call-recorder нет — не показывать.

2. **API для закрытия цели нет.** Если без шага не закрываются Ц-1…Ц-5 или описанный сценарий, а нужного API (метода, поля, события) нет — это дыра контракта, не повод нарисовать фейк. Цель не пропускать. На экране не делать вид, что шаг уже работает. Написать прямо: цель N / сценарий такой-то, чего в API нет, без этого цель не закрывается.

3. **Текущий API цели закрывает — остальное убрать.** Если контракт, который есть, для этих целей и сценариев подходит, все прочие украшения снимать, не держать «на всякий случай».

Состояние на 22.09.2026 — вкладка «Постановка», якорь `#sa-status`.

## Дыры API относительно целей

Сверка живого контура с `http-call-recorder` (enroll / stream / audio: ключ, пропуск, файл, источник, событие подсказки на том же stream). Имена полей в проводе — как в приёмнике; здесь состав из `Требования/`, не выдуманный URL.

**Закрывается тем, что в контракте есть**

- Ц-2: звук на сервер организации, не в облако вендора; без связи — очередь на устройстве, затем тот же приём.
- Ц-3 в части источника: компьютер / телефон / диктофон в пакете («откуда звук»).
- Ц-5 в части канала: подсказка — событие на stream, не отдельный чат; пустого события нет — на экране нет карточки.

**Задачи на бэкенд — три разные команды**

| Кому | Задача | Готово, когда |
|---|---|---|
| Приём звука (`enroll` / `stream` / `audio`) | Принять вместе с файлом: откуда карточка (календарь / номер / выбрали / нет), id карточки если есть, «не клиент». Файл без id принять. В продажи без id не отдавать. Имена в проводе — как у приёмника | Планёрка не создаёт задачу. «Не клиент» не едет в продажи |
| Система продаж | Событие только с id карточки. Встреча или звонок в канале «Встречи и звонки». Компанию и сделку не создавать. Черновик полей до «Подтвердить». Касание в счёте | Руководитель видит встречу, черновик и число касаний на ООО «Норд» |
| Сервер подсказок (то же соединение, что звук) | Есть id — прочитать карточку только на чтение и прислать в событии подсказки. Писать в карточку нельзя. Нет id — факты карточки не слать | Во время звонка факты из карточки, после звонка карточка не изменилась |
| Не этот бэкенд | Список файлов на диктофоне и скачать по Bluetooth — телефон и железо, не `enroll`. Защиты на потерянном диктофоне нет. Шифрование устройства — целевое условие будущей клиентской поставки, не текущая возможность. Поток AIREC на стенде подтверждён разработчиком; сквозного прогона с физическим диктофоном нет | Очная запись доезжает тем же приёмом. Защиту как существующую не обещают |

**Не дыра цели — снято с экрана**

Заряд, гигабайты флеш, «слушать живой звук», «начать запись на устройстве», квота, шаблоны, «Спросить ИИ», конспект как замена живой подсказки, персонализация и память, «как разбирать записи», язык распознавания на выбор, автоподпись говорящих, свой словарь, отдельный экран очереди «Отправка», чат поддержки, отзыв о программе, справочный центр, отметки и снимок в заметку, «заметка готова», разделение голосов как живая настройка.

## Живой проход: кнопка → API

Проход 22.09.2026. Три исхода: есть в приёме звука / дыра цели / клиент или снято.

| Что на экране | Исход |
|---|---|
| Начать / стоп записи | `enroll` + `stream` или `audio`, источник |
| Подсказка во время разговора | событие на `stream`; пустого нет — карточки нет |
| Сервер задан / адрес / связь | нужно, чтобы открыть приём; адрес задаёт администратор |
| Список, папки, корзина | клиент: файлы на устройстве, не метод приёма |
| Откуда запись | поле источника в пакете |
| Забрать файлы с диктофона | дыра Ц-2 / Ц-3: Bluetooth не `enroll`. Кнопки «забрать» сняты, экран не притворяется |
| Ушла / очередь | очередь — файл на устройстве до успеха `audio`/`stream`, не ресурс API |
| Нет id, указать карточку, не клиент | дыра Ц-1: в `enroll`/`stream` этих полей нет |
| Выгрузить расшифровку | клиент: уже полученный текст в файл |
| Язык меню, тема, виджет, микрофон ОС | клиент, не приём |
| Режим записи, профиль подсказок | политика организации; в `enroll` имён не видели — показ, не форма |
| Приватный звонок | в приёме поля нет — показ политики, не тумблер |
| Подсказка из карточки сделки | дыра Ц-5 |
| Отзыв, чат поддержки, персонализация, память, автоподпись, Отправка | нет API — снято с живого меню |
