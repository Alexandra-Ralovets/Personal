# FlowMeet: Видно, как шла работа с клиентом (Ц-4)

Стадия: Для разработки. Счёт касаний — в системе продаж, а не новый экран во FlowMeet.

Роль цели: Целевое поведение. Бизнес-план: цель Ц-4 (20.08.2026). Спрос на счёт в плане не подтверждён.

Ключ задачи PRD: [ТРЕБУЕТ УТОЧНЕНИЯ]

О продукте: FlowMeet записывает рабочий разговор и кладёт его на карточку клиента в системе продаж. Звук, текст и архив остаются на сервере вашей компании, а не у стороннего вендора.

В примерах клиент — тестовое ООО «Норд», не живая компания.

Файл собран из `tools/sa_content_*.py` скриптом `tools/build_requirements.py`; правки вносятся в источник, не сюда.

## Глоссарий

Общий словарь постановки. Термины, которыми пользуется эта цель, — те же, что в остальных целях.

| Термин | Определение |
|--------|-------------|
| Разговор | Одна запись от старта до стопа. Идентификатор — `call_id` (в пакете клиента поле называется `recording_id`; это один и тот же идентификатор, имя закрепляется в ОВ-1.1). |
| Источник записи | Откуда звук: компьютер, телефон или диктофон. Передаётся вместе с разговором. |
| Устройственный канал | Приём звука и технических данных по ключу устройства (`enroll`, `stream`, `audio`). По этому каналу устройство не выбирает клиента и не читает систему продаж. |
| Карточка | Уже существующая карточка клиента в системе продаж; идентификатор — id карточки. FlowMeet карточек не создаёт. |
| Привязка | Подтверждённая связь разговора с карточкой. Источник: встреча календаря, у которой уже есть карточка; номер телефона контакта карточки; карточка, которую выбрал сотрудник. Название компании из речи привязкой не является. |
| Кандидат | Карточка, предположенная по речи. Хранится отдельно от привязки и до подтверждения сотрудником ничего не открывает и ничего не создаёт. |
| Тип разговора | Клиентский, «не клиент» (планёрка, собеседование, внутренний разбор) или не определён. |
| Канал «Встречи и звонки» | Существующий канал на карточке; туда же попадают встречи из календаря и почта. |
| Черновик полей | Значения из разговора на карточке, пока сотрудник не нажал «Подтвердить». |
| Касание | Клиентский разговор с подтверждённой привязкой, доехавший в канал «Встречи и звонки». Не отметка, поставленная руками; не планёрка; не запись в очереди. |
| Контур организации | Сервер организации: на нём звук, расшифровка и архив. Не облачный сервис вендора. |
| Очередь | Запись на устройстве, пока сервер организации недоступен или не подтвердил приём. |
| Приватная запись | Запись, которую сотрудник сделал приватной, если это разрешила организация: остаётся только на устройстве, всё, что уже ушло на сервер, отзывается. |
| Живая подсказка | Карточка подсказки на экране записи во время разговора: вид, заголовок, текст, источник. Не консультация после встречи и не «Спросить ИИ». |
| Профиль подсказок | Набор подсказок для вида работы (продажи, поддержка, найм, разработка). Задаёт организация. |

## Сквозные правила

| № | Правило | Содержание |
|---|---------|------------|
| СР-1 | Два контура записи | Устройство передаёт звук и технические данные разговора по устройственному каналу. Карточку выбирает вошедший сотрудник или серверная интеграция (календарь, телефония) отдельной операцией. Сервер проверяет, что карточка существует и что у сотрудника есть право на неё, и пишет аудит. Оба контура сходятся по `call_id`. |
| СР-2 | В продажи — только с привязкой | Событие в систему продаж создаётся только для клиентского разговора с подтверждённой привязкой. Без привязки запись хранится на сервере организации, в продажах нет ни события, ни задачи. |
| СР-3 | Кандидат — не привязка | Компания, узнанная по речи, не открывает факты карточки, не создаёт встречу и не считается касанием до подтверждения сотрудником. |
| СР-4 | Один разговор — одно событие | Повторная отправка того же разговора (тот же `call_id` и контрольная сумма файла) принимается как успех и второго события не создаёт. Поздняя привязка запускает доставку того же разговора, а не нового. |
| СР-5 | Во время разговора продажи не меняются | Ни запись, ни подсказка во время разговора ничего не пишут в систему продаж. |
| СР-6 | Запись не теряется | Нет связи — запись остаётся в очереди на устройстве и уходит на тот же сервер организации, когда связь появится. Очередь ничего не удаляет, пока сервер не подтвердил приём. |
| СР-7 | Приватная запись | Если организация разрешила, сотрудник может сделать запись приватной. Она остаётся на устройстве; всё, что уже ушло на сервер, отзывается. В продажи и в счёт касаний такая запись не попадает. |

## Бизнес-ценность

Руководитель видит, сколько встреч и звонков было до решения, сколько дней между ними и где касания перестают двигать сделку, по доехавшим разговорам, а не по ручным отметкам.

## Цели

- На карточке клиента видно число касаний по разговорам, которые доехали.
- Видны промежутки между касаниями.
- Внутренние разговоры и приватные записи в счёт клиента не входят.

**Мера:** Число касаний и дни между ними (П-19). Не считали.

**Входит в контур:**

- какие данные FlowMeet поставляет в событие;
- правила, что считается касанием, а что нет;
- дедупликация повторов.

**Не входит:**

- экран счёта и «дни между» — не FlowMeet; его рисует система продаж или PRD-1074;
- воронка касаний и аналитика в приложении записи;
- требования к скорости появления цифры;
- восстановление старых касаний.

---

## Проблемы

**AS-IS (как сейчас):**

Видны отметки, которые продавец поставил сам. Разговоры вне онлайн-конференции — слепое пятно. Канал встреч считает почту и календарь; голос FlowMeet не входит. Сделка может стоять месяцами при том, что разговоры были или не были.

**Последствия:**

Владелец процесса не отличает «не звонили» от «звонили, но в систему не попало». Управление по пересказу.

**Масштаб:** Не считали; вопрос заказчику не задавался.

## Пользовательские кейсы

### К-4.1. Счётчик после разговора

Как руководитель, я хочу видеть, сколько разговоров с ООО «Норд» доехало, чтобы не верить только галочкам продавца.

| | |
|--|--|
| **Актор** | Руководитель |
| **Ситуация** | На карточке ООО «Норд» канал «Встречи и звонки» уже есть. Клиентский разговор FlowMeet доехал (Ц-1). |
| **Проблема сейчас** | Счётчик не меняется, руководитель думает, что касания не было. |
| **Ожидаемый результат** | Счётчик вырос на это касание. В ленте строка разговора, не только почта. |
| **Требования** | ФТ-4.1, ФТ-4.2 |

### К-4.2. Дни между касаниями

Как руководитель, я хочу видеть дни между касаниями, чтобы понять простой.

| | |
|--|--|
| **Актор** | Руководитель |
| **Ситуация** | На карточке минимум два доехавших касания с датами. |
| **Проблема сейчас** | Не видно, стояла ли работа неделю или месяц. |
| **Ожидаемый результат** | Даты событий уходят вместе с записью; система продаж (или PRD-1074) показывает промежутки. Если экрана нет — данные всё равно есть, а цифру FlowMeet не рисует. |
| **Требования** | ФТ-4.1, ФТ-4.3 |

### К-4.3. Касаний много, этап стоит

Как руководитель, я хочу, чтобы этап сделки сам не закрывался от факта касания, чтобы решение по этапу оставалось за человеком.

| | |
|--|--|
| **Актор** | Руководитель |
| **Ситуация** | Разговоры доезжают, маршрут сделки не закрыт. |
| **Проблема сейчас** | Либо этап сам прыгнет от записи, либо касания невидимы. |
| **Ожидаемый результат** | Касания видны. Этап запись не двигает (как в Ц-1). |
| **Требования** | ФТ-4.5 |

### К-4.4. Планёрка, приватная запись и повтор не считаются

Как руководитель, я не хочу, чтобы планёрка, приватная запись или повторная отправка считались касанием клиента.

| | |
|--|--|
| **Актор** | Руководитель |
| **Ситуация** | Внутренний разговор без клиента; приватная запись; повторно отправленный файл. |
| **Проблема сейчас** | Счётчик клиента растёт от лишнего — картина вранья. |
| **Ожидаемый результат** | Не касание: разговор без привязки, «не клиент», приватная запись, запись в очереди, повтор того же `call_id`. |
| **Требования** | ФТ-4.2, ФТ-4.4 |

## Corner-cases

- Два файла одной встречи с одним `call_id` (обрыв и досылка): одно касание.
- Календарь без записи и запись той же встречи: в пакете один id встречи календаря; две строки в ленте, пока канал не склеил, — не чинится вторым счётчиком во FlowMeet.
- Длинная встреча диктофона, пришедшая несколькими записями: см. ОВ-3.2 и ОВ-4.3.

---

## Критерии приёмки

- **AC-4.1:** Доехал клиентский разговор FlowMeet → счётчик канала вырос на одно касание. (ФТ-4.1, ФТ-4.2)
- **AC-4.2:** Планёрка или приватная запись → счётчик клиента не вырос. (ФТ-4.2)
- **AC-4.3:** Запись в очереди → счётчик не вырос. (ФТ-4.2)
- **AC-4.4:** Повтор той же записи → второе касание не создано. (ФТ-4.4)
- **AC-4.5:** В приложении FlowMeet нет отдельной воронки касаний; событие несёт `call_id`, время, источник, id календаря. (ФТ-4.1, ФТ-4.3)
- **AC-4.6:** Этап сделки от касания сам не закрылся. (ФТ-4.5)
