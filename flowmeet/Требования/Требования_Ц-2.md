# FlowMeet: Запись остаётся в контуре организации (Ц-2)

Стадия: Для разработки. Макет — прототип FlowMeet. Чужое облако в продукт не входит.

Роль цели: Условие допуска: без него продукт не пускают в периметр организации.

Ключ задачи PRD: [ТРЕБУЕТ УТОЧНЕНИЯ]

О продукте: FlowMeet записывает рабочий разговор и кладёт его на карточку клиента в системе продаж. Звук, текст и архив остаются на сервере вашей компании, а не у стороннего вендора.

В примерах клиент — тестовое ООО «Норд», не живая компания.

Файл собран из `tools/sa_content_*.py` скриптом `tools/build_requirements.py`; правки вносятся в источник, не сюда.

## Глоссарий

Общий словарь постановки. Термины, которыми пользуется эта цель, — те же, что в остальных целях.

| Термин | Определение |
|--------|-------------|
| Разговор | Одна запись от старта до стопа. Идентификатор — `call_id` (в пакете клиента поле называется `recording_id`; это один и тот же идентификатор, имя закрепляется в ОВ-1.1). |
| Источник записи | Откуда звук: компьютер, телефон или диктофон. Передаётся вместе с разговором. |
| Устройственный канал | Приём звука и технических данных по ключу устройства (`enroll`, `stream`, `audio`). По этому каналу устройство не выбирает клиента и не читает систему продаж. |
| Карточка | Уже существующая карточка клиента в системе продаж; идентификатор — id карточки. FlowMeet карточек не создаёт. |
| Привязка | Подтверждённая связь разговора с карточкой. Источник: встреча календаря, у которой уже есть карточка; номер телефона контакта карточки; карточка, которую выбрал сотрудник. Название компании из речи привязкой не является. |
| Кандидат | Карточка, предположенная по речи. Хранится отдельно от привязки и до подтверждения сотрудником ничего не открывает и ничего не создаёт. |
| Тип разговора | Клиентский, «не клиент» (планёрка, собеседование, внутренний разбор) или не определён. |
| Канал «Встречи и звонки» | Существующий канал на карточке; туда же попадают встречи из календаря и почта. |
| Черновик полей | Значения из разговора на карточке, пока сотрудник не нажал «Подтвердить». |
| Касание | Клиентский разговор с подтверждённой привязкой, доехавший в канал «Встречи и звонки». Не отметка, поставленная руками; не планёрка; не запись в очереди. |
| Контур организации | Сервер организации: на нём звук, расшифровка и архив. Не облачный сервис вендора. |
| Очередь | Запись на устройстве, пока сервер организации недоступен или не подтвердил приём. |
| Приватная запись | Запись, которую сотрудник сделал приватной, если это разрешила организация: остаётся только на устройстве, всё, что уже ушло на сервер, отзывается. |
| Живая подсказка | Карточка подсказки на экране записи во время разговора: вид, заголовок, текст, источник. Не консультация после встречи и не «Спросить ИИ». |
| Профиль подсказок | Набор подсказок для вида работы (продажи, поддержка, найм, разработка). Задаёт организация. |

## Сквозные правила

| № | Правило | Содержание |
|---|---------|------------|
| СР-1 | Два контура записи | Устройство передаёт звук и технические данные разговора по устройственному каналу. Карточку выбирает вошедший сотрудник или серверная интеграция (календарь, телефония) отдельной операцией. Сервер проверяет, что карточка существует и что у сотрудника есть право на неё, и пишет аудит. Оба контура сходятся по `call_id`. |
| СР-2 | В продажи — только с привязкой | Событие в систему продаж создаётся только для клиентского разговора с подтверждённой привязкой. Без привязки запись хранится на сервере организации, в продажах нет ни события, ни задачи. |
| СР-3 | Кандидат — не привязка | Компания, узнанная по речи, не открывает факты карточки, не создаёт встречу и не считается касанием до подтверждения сотрудником. |
| СР-4 | Один разговор — одно событие | Повторная отправка того же разговора (тот же `call_id` и контрольная сумма файла) принимается как успех и второго события не создаёт. Поздняя привязка запускает доставку того же разговора, а не нового. |
| СР-5 | Во время разговора продажи не меняются | Ни запись, ни подсказка во время разговора ничего не пишут в систему продаж. |
| СР-6 | Запись не теряется | Нет связи — запись остаётся в очереди на устройстве и уходит на тот же сервер организации, когда связь появится. Очередь ничего не удаляет, пока сервер не подтвердил приём. |
| СР-7 | Приватная запись | Если организация разрешила, сотрудник может сделать запись приватной. Она остаётся на устройстве; всё, что уже ушло на сервер, отзывается. В продажи и в счёт касаний такая запись не попадает. |

## Бизнес-ценность

Звук, расшифровка и архив рабочих разговоров остаются внутри периметра организации. Служба безопасности заказчика может допустить поставку.

## Цели

- Звук, текст и архив разговора хранятся на сервере организации, а не у внешнего облачного вендора.
- Нет связи — запись доезжает на тот же сервер, когда связь появится.
- Сотрудник не выбирает, куда уходит запись: сервер задаёт организация.

**Мера:** Доля записей, покинувших контур, — ноль. Числа замера нет.

**Входит в контур:**

- назначение записи и состояние «сервер не задан»;
- очередь на устройстве;
- запись с диктофона (ввоз на телефон и отправка);
- приватная запись.

**Не входит:**

- шифрование устройства и защита потерянного диктофона — не обещаются, пока их нет;
- правовой режим записи и согласие собеседника — вне клиента;
- личный потребительский режим — в поставке с закрытым контуром выключен.

---

## Проблемы

**AS-IS (как сейчас):**

Облачный диктофон и потребительский блокнот отправляют звук наружу. У организации с закрытым контуром служба безопасности вправе закрыть поставку. Запись онлайн-конференций у компании уже есть; разговор вне конференции часто уходит в чужой сервис или никуда.

**Последствия:**

Заказчик с режимным объектом продукт не рассматривает: запись либо запрещена, либо живёт вне предприятия.

**Масштаб:** Целевое значение меры — ноль записей вне контура. Факт не замерен.

## Акторы и ролевая модель

| Актор | Описание | Права в рамках функции |
|-------|----------|------------------------|
| Сотрудник | Пишет разговор в FlowMeet. | Не выбирает облако и не меняет адрес сервера. |
| Администратор организации | Задаёт сервер организации и разрешения (например, приватную запись). | Задаёт, куда уходит звук. |
| Служба безопасности заказчика | Решает, допускать ли поставку. | Не пользователь FlowMeet. |
| Сервер организации | Приём, расшифровка, архив. | Единственное место хранения после отправки. |

## Пользовательские кейсы

### К-2.1. Конец записи при связи

Как сотрудник, я хочу, чтобы запись уходила на сервер моей компании, чтобы звук не оказывался в чужом облаке.

| | |
|--|--|
| **Актор** | Сотрудник |
| **Ситуация** | Устройство в режиме организации, сервер задан, связь есть. |
| **Проблема сейчас** | Если звук уйдёт к облачному вендору, служба безопасности закроет поставку. |
| **Ожидаемый результат** | Файл на сервере организации. Расшифровка и архив там же. Чужого облака в цепочке нет. |
| **Требования** | ФТ-2.1 |

### К-2.2. Нет связи

Когда нет сети, я хочу, чтобы запись доехала на сервер компании позже, а не в облако и не пропала.

| | |
|--|--|
| **Актор** | Сотрудник |
| **Ситуация** | Сервер организации недоступен. |
| **Проблема сейчас** | Запись пропадёт или приложение предложит облако «пока нет своей сети». |
| **Ожидаемый результат** | Файл лежит в очереди на устройстве. Связь появилась — файл ушёл на тот же сервер. Метка «ждёт сеть» снимается. |
| **Требования** | ФТ-2.3 |

### К-2.3. Сервер не задан

Как сотрудник, я хочу сразу понять, почему запись не начинается, если сервер не задан.

| | |
|--|--|
| **Актор** | Сотрудник |
| **Ситуация** | Администратор ещё не задал сервер организации. |
| **Проблема сейчас** | Молчаливая запись «в никуда» или отправка в облако по умолчанию. |
| **Ожидаемый результат** | Рабочая запись не начинается. На экране прямо: «сервер организации не задан». В облако вендора ничего не уходит. |
| **Требования** | ФТ-2.2 |

### К-2.4. Сотрудник не выбирает облако

Как администратор организации, я хочу задать сервер организации, чтобы сотрудник не выбирал облако.

| | |
|--|--|
| **Актор** | Администратор организации |
| **Ситуация** | Режим организации. |
| **Проблема сейчас** | Если можно нажать «в облако», контур держится на дисциплине, а не на продукте. |
| **Ожидаемый результат** | В приложении нет действия «отправить вендору». Запись идёт на сервер, который задал администратор. |
| **Требования** | ФТ-2.1, ФТ-2.2 |

### К-2.5. Запись с диктофона

Как сотрудник, я хочу писать с диктофона на тот же сервер, что с компьютера.

| | |
|--|--|
| **Актор** | Сотрудник |
| **Ситуация** | Диктофон подключён к телефону по Bluetooth. Включён ввоз записей. |
| **Проблема сейчас** | Очный звук уходит в облако диктофона, а компьютерный — в контур. Для службы безопасности это дыра. |
| **Ожидаемый результат** | Новые записи с диктофона скачиваются на телефон и автоматически уходят на сервер организации. Если сервер не принял запись, сотрудник видит это и выбирает: отправить снова или удалить с телефона. |
| **Требования** | ФТ-2.4 |

### К-2.6. Приватная запись

Как сотрудник, я хочу сделать личный разговор приватным, чтобы он не попал на сервер.

| | |
|--|--|
| **Актор** | Сотрудник |
| **Ситуация** | Идёт запись. Организация разрешила приватные записи. |
| **Проблема сейчас** | Личный разговор может оказаться на сервере организации. |
| **Ожидаемый результат** | После подтверждения запись остаётся только на устройстве, а всё, что уже ушло на сервер, отзывается. Подсказки на время приватной записи не идут. |
| **Требования** | ФТ-2.5 |

| **Альт. сценарий B** | **Приватные записи запрещены организацией:** Действия «Сделать приватной» нет; записывается любой разговор. |
| **Постусловия** | Приватная запись только на устройстве; в продажах и в счёте касаний её нет. |

---

## Corner-cases

- Файл в очереди на ноутбуке вне офиса — не уход к вендору: контур нарушен, только если файл оказался у внешнего облака.
- Потерянный диктофон: кто взял устройство, может прослушать записи; защиты нет.
- Длинная встреча на диктофоне приходит несколькими записями (длина одной записи — настройка диктофона); каждая запись — отдельный разговор (ОВ-3.2).

---

## Критерии приёмки

- **AC-2.1:** Конец записи при связи → файл на сервере организации, не у внешнего облачного вендора. (ФТ-2.1)
- **AC-2.2:** Конец записи без связи → очередь; после связи тот же сервер; метка «ждёт сеть» снята. (ФТ-2.3)
- **AC-2.3:** Запись с диктофона → тот же сервер; при отказе сервера видны «Отправить снова» и «Удалить с этого телефона». (ФТ-2.4)
- **AC-2.4:** В приложении сотрудника нет отправки в чужое облако. (ФТ-2.1)
- **AC-2.5:** Сервер не задан → запись не начинается, сообщение показано, в облако ничего не уходит. (ФТ-2.2)
- **AC-2.6:** Приватная запись → на сервер не уходит, ранее отправленное отозвано, в продажах и счёте касаний её нет. (ФТ-2.5)
- **AC-2.7:** В приложении нет обещаний защиты потерянного диктофона и шифрования устройства. (ФТ-2.6)
