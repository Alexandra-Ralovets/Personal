# FlowMeet: Картина по клиенту у предприятия (Ц-3)

Стадия: Для разработки. Карточка клиента — система продаж. FlowMeet даёт разговоры всех источников в тот же путь, что Ц-1.

Роль цели: Целевое поведение. Бизнес-план: цель Ц-3 (20.08.2026). Нужна ли заказчику полнота всех видов вместе, в плане не спрашивали.

Ключ задачи PRD: [ТРЕБУЕТ УТОЧНЕНИЯ]

О продукте: FlowMeet записывает рабочий разговор и кладёт его на карточку клиента в системе продаж. Звук, текст и архив остаются на сервере вашей компании, а не у стороннего вендора.

В примерах клиент — тестовое ООО «Норд», не живая компания.

Файл собран из `tools/sa_content_*.py` скриптом `tools/build_requirements.py`; правки вносятся в источник, не сюда.

## Глоссарий

Общий словарь постановки. Термины, которыми пользуется эта цель, — те же, что в остальных целях.

| Термин | Определение |
|--------|-------------|
| Разговор | Одна запись от старта до стопа. Идентификатор — `call_id` (в пакете клиента поле называется `recording_id`; это один и тот же идентификатор, имя закрепляется в ОВ-1.1). |
| Источник записи | Откуда звук: компьютер, телефон или диктофон. Передаётся вместе с разговором. |
| Устройственный канал | Приём звука и технических данных по ключу устройства (`enroll`, `stream`, `audio`). По этому каналу устройство не выбирает клиента и не читает систему продаж. |
| Карточка | Уже существующая карточка клиента в системе продаж; идентификатор — id карточки. FlowMeet карточек не создаёт. |
| Привязка | Подтверждённая связь разговора с карточкой. Источник: встреча календаря, у которой уже есть карточка; номер телефона контакта карточки; карточка, которую выбрал сотрудник. Название компании из речи привязкой не является. |
| Кандидат | Карточка, предположенная по речи. Хранится отдельно от привязки и до подтверждения сотрудником ничего не открывает и ничего не создаёт. |
| Тип разговора | Клиентский, «не клиент» (планёрка, собеседование, внутренний разбор) или не определён. |
| Канал «Встречи и звонки» | Существующий канал на карточке; туда же попадают встречи из календаря и почта. |
| Черновик полей | Значения из разговора на карточке, пока сотрудник не нажал «Подтвердить». |
| Касание | Клиентский разговор с подтверждённой привязкой, доехавший в канал «Встречи и звонки». Не отметка, поставленная руками; не планёрка; не запись в очереди. |
| Контур организации | Сервер организации: на нём звук, расшифровка и архив. Не облачный сервис вендора. |
| Очередь | Запись на устройстве, пока сервер организации недоступен или не подтвердил приём. |
| Приватная запись | Запись, которую сотрудник сделал приватной, если это разрешила организация: остаётся только на устройстве, всё, что уже ушло на сервер, отзывается. |
| Живая подсказка | Карточка подсказки на экране записи во время разговора: вид, заголовок, текст, источник. Не консультация после встречи и не «Спросить ИИ». |
| Профиль подсказок | Набор подсказок для вида работы (продажи, поддержка, найм, разработка). Задаёт организация. |

## Сквозные правила

| № | Правило | Содержание |
|---|---------|------------|
| СР-1 | Два контура записи | Устройство передаёт звук и технические данные разговора по устройственному каналу. Карточку выбирает вошедший сотрудник или серверная интеграция (календарь, телефония) отдельной операцией. Сервер проверяет, что карточка существует и что у сотрудника есть право на неё, и пишет аудит. Оба контура сходятся по `call_id`. |
| СР-2 | В продажи — только с привязкой | Событие в систему продаж создаётся только для клиентского разговора с подтверждённой привязкой. Без привязки запись хранится на сервере организации, в продажах нет ни события, ни задачи. |
| СР-3 | Кандидат — не привязка | Компания, узнанная по речи, не открывает факты карточки, не создаёт встречу и не считается касанием до подтверждения сотрудником. |
| СР-4 | Один разговор — одно событие | Повторная отправка того же разговора (тот же `call_id` и контрольная сумма файла) принимается как успех и второго события не создаёт. Поздняя привязка запускает доставку того же разговора, а не нового. |
| СР-5 | Во время разговора продажи не меняются | Ни запись, ни подсказка во время разговора ничего не пишут в систему продаж. |
| СР-6 | Запись не теряется | Нет связи — запись остаётся в очереди на устройстве и уходит на тот же сервер организации, когда связь появится. Очередь ничего не удаляет, пока сервер не подтвердил приём. |
| СР-7 | Приватная запись | Если организация разрешила, сотрудник может сделать запись приватной. Она остаётся на устройстве; всё, что уже ушло на сервер, отзывается. В продажи и в счёт касаний такая запись не попадает. |

## Бизнес-ценность

Полная картина по клиенту хранится у предприятия, а не в голове менеджера. После смены продавца разговоры с клиентом не пропадают.

## Цели

- Клиентские разговоры любого источника — компьютер, телефон, диктофон — оказываются на карточке клиента.
- Картина живёт на карточке в системе продаж, а не в личном списке записей продавца.
- Новый продавец или руководитель видит доехавшие разговоры без вопросов к предшественнику.

**Мера:** Доля разговоров с клиентом, доехавших в платформу (П-14). Не замерено; знаменатель «все разговоры» во FlowMeet не считается.

**Входит в контур:**

- три источника записи и их различия на входе;
- общий путь после приёма — тот же, что в Ц-1;
- видимость доехавшего разговора на карточке и в списке приложения.

**Не входит:**

- разрезание одной записи диктофона на несколько встреч;
- запись iPhone из фона — только то, что человек записал сам;
- внутренние разговоры без клиента;
- отдельный отчёт «все разговоры» сверх карточки.

## Проблемы

**AS-IS (как сейчас):**

Самый полный носитель информации о клиенте — сам менеджер. Онлайн-конференции компания уже может писать. Встречи в переговорной, на объекте и звонки по телефону в платформу часто не попадают. Сменился продавец — картина ушла с человеком.

**Последствия:**

Руководитель и новый продавец не видят, что говорили с клиентом очно или по телефону. Ц-1 заполняет поля только у тех разговоров, которые доехали; остальные как не существовали.

**Масштаб:** Не замерено.

## Пользовательские кейсы

### К-3.1. Онлайн-встреча с компьютера

Как продавец, я хочу, чтобы онлайн-встреча с ООО «Норд» доехала на карточку, чтобы она не осталась только в конференции.

| | |
|--|--|
| **Актор** | Продавец |
| **Ситуация** | Встреча в Teams или аналоге. FlowMeet пишет на компьютере; привязка есть. |
| **Проблема сейчас** | Разговор остаётся в конференции или в голове, на карточке его нет. |
| **Ожидаемый результат** | После стопа путь Ц-1: на карточке встреча в «Встречах и звонках». |
| **Требования** | ФТ-3.1, ФТ-3.2, ФТ-3.3 |

### К-3.2. Переговорная или объект

Как продавец, я хочу, чтобы встреча в переговорной с диктофона доехала на ту же карточку.

| | |
|--|--|
| **Актор** | Продавец |
| **Ситуация** | Встреча не в конференции. Пишет диктофон (смешанный звук). |
| **Проблема сейчас** | Очный разговор для предприятия как будто не существовал. |
| **Ожидаемый результат** | Тот же путь на ту же карточку. В ленте видно устройство, а не письмо. |
| **Требования** | ФТ-3.1, ФТ-3.2, ФТ-3.4 |

### К-3.3. Звонок по телефону

Как продавец, я хочу, чтобы звонок по телефону доехал на ту же карточку.

| | |
|--|--|
| **Актор** | Продавец |
| **Ситуация** | Звонок контакту карточки. Продавец записал его в приложении на телефоне. |
| **Проблема сейчас** | Факт звонка продавец пишет комментарием или не пишет. |
| **Ожидаемый результат** | Звонок появляется в канале той же карточки; привязка — номер телефона контакта. |
| **Требования** | ФТ-3.1, ФТ-3.5 |

### К-3.4. Сменился продавец

Как новый продавец, я хочу видеть разговоры на карточке предприятия, чтобы не спрашивать предшественника.

| | |
|--|--|
| **Актор** | Новый продавец, руководитель |
| **Ситуация** | ООО «Норд» передали другому. Прежний продавец вёл клиента, разговоры доехали. |
| **Проблема сейчас** | Картина ушла с человеком: файлы в его телефоне, в платформе пусто. |
| **Ожидаемый результат** | Новый человек открывает карточку и видит доехавшие встречи и звонки. |
| **Требования** | ФТ-3.3 |

### К-3.5. Список в приложении — не архив предприятия

Как продавец, я не хочу, чтобы «всё записано» означало «файлы лежат у меня в приложении», когда карточки клиента в платформе нет.

| | |
|--|--|
| **Актор** | Продавец |
| **Ситуация** | В FlowMeet полный список записей, привязки к карточке нет. |
| **Проблема сейчас** | Цель Ц-3 звучит как «всё записано», а у предприятия ничего нет. |
| **Ожидаемый результат** | Картина считается выполненной, только если разговор на карточке в системе продаж. Список в приложении показывает состояния, а не архив предприятия. |
| **Требования** | ФТ-3.3 |

## Corner-cases

- Несколько встреч подряд в одной записи диктофона: одно событие, резать не будем.
- iPhone без нажатой записи: нет записи — нет события.

## Критерии приёмки

- **AC-3.1:** Онлайн-встреча с привязкой → на карточке ООО «Норд». (ФТ-3.1, ФТ-3.2)
- **AC-3.2:** Запись диктофоном с привязкой → на той же карточке, источник «диктофон». (ФТ-3.1, ФТ-3.2, ФТ-3.4)
- **AC-3.3:** Звонок с привязкой по номеру → на той же карточке; на iPhone запись только по действию человека. (ФТ-3.1, ФТ-3.5)
